# Testing and evaluation results

**Run date:** 2026-11-03  
**Scope:** Synthetic agreement extraction, deterministic validation, review and monitoring workflows, and live OpenRouter integration.

## Dataset

The evaluation set contains **19 synthetic cases**, **20 synthetic PDFs**, **18 expected obligations**, and **26 manually annotated evidence quotations**. It is located in `backend/evaluation_dataset/TC01` through `TC19`. Case TC14 contains both an original agreement and an amendment.

Coverage includes financial thresholds and comparison operators, units and measurement bases, reporting dates and calculation rules, affirmative and negative covenants, exceptions and conditions, remote definitions, cross-references, uncertainty escalation, missing information, duplicates, long-document/page-12 text, amendment threshold changes, a reporting-only agreement, a non-covenant lookalike, and an invalid PDF.

The synthetic agreement text and expected JSON were authored as separate files; expected values were not generated by the LLM. Dataset integrity tests verify schema shape and that annotated evidence is present on its cited PDF page. These checks establish annotation and traceability integrity, not legal correctness.

## Live OpenRouter result

The local configuration was read without printing the key. The configured model was `openai/gpt-6.1-terra` and the base URL was OpenRouter's API endpoint. One synthetic extraction case (TC01) reached the real provider. OpenRouter returned **HTTP 402**, represented as `provider_insufficient_credits`; it returned no model completion. The run produced **zero candidates**. The evaluator stopped further live cases after this provider error.

A later rerun of the combined evaluation remained pending without a recorded provider response and was interrupted. It is not counted as a successful or completed provider result. No private agreement was submitted.

The result is an integration failure, not a model-quality score. It does not establish that the requested model or structured-output configuration works. ## Offline pipeline and workflow results

The mock provider was supplied with hand-authored expected payloads to exercise the same upload, processing, schema validation, evidence validation, candidate persistence, and relational Evidence storage paths. These are deterministic test doubles, not LLM predictions. Consequently, **no mock accuracy score is computed**.

The recorded mock run passed **19/19 case pipeline checks** with **0 failures**. It verified candidate schema validity, page/quote evidence checks, and consistency between evidence embedded in the complete canonical payload and the relational Evidence table. The invalid-PDF case passed by confirming rejection.

All **12 full-workflow checks** passed in the isolated evaluation database:

- Reject a candidate and confirm it is absent from the approved register.
- Correct a candidate using a complete replacement object and validate the correction.
- Approve the corrected revision and confirm it appears in the register.
- Create and update a quarterly monitoring period.
- Compare the amendment, detect the expected threshold change from 3.50 to 4.00, and accept the reviewed change.
- Confirm audit events were written.

These checks verify application behavior using synthetic data and mock provider output only. They do not verify live extraction quality or browser automation.

## Bugs discovered and fixes implemented

| Issue | Root cause | Fix and regression coverage |
|---|---|---|
| Affirmative insurance/compliance duties could not be represented in the canonical category vocabulary. | Extraction category taxonomy only covered financial, reporting, and negative covenant categories. | Added `affirmative_covenant` to canonical schema v1.1.0, provider prompt/schema, filtering, API schema version, and frontend labels. Backend extraction/schema tests cover the category. |
| A valid empty `obligations` response was treated as malformed/partial. | The service treated an empty list like invalid model output. | Empty valid batches now complete without fabricated candidates and carry an informational `no_obligations_returned` finding. A backend regression test covers this behavior. |
| Insufficient provider credits could appear as an opaque extraction failure. | Provider errors were not normalized into safe, actionable status fields. | HTTP 402 is reported as `provider_insufficient_credits`; run metadata and UI expose a safe message without response body or key. Regression tests cover provider and UI error handling. |
| The extraction action could be clicked while document page indexing was still loading. | The button depended on extraction-run state but not the selected version's page-load completion. | Frontend now waits for pages to load before enabling extraction; the workflow test waits for this enabled state. |

No expected ground-truth answer was changed to make a test pass. Synthetic outputs and database state were isolated from the normal development database.

## Findings and limitations

- **Live LLM extraction remains unverified.** The provider did not return a completion because of HTTP 402. Add credits or resolve the account limit before a new authorized evaluation.
- **No real extraction errors or successes can be scored.** There is no model response to compare with the gold annotations, so field-level and obligation metrics remain null.
- **Mock results are not accuracy evidence.** The mock payloads intentionally come from the expected set and test plumbing and workflow invariants.
- **No live browser-driven end-to-end run was performed for this evaluation.** Frontend Vitest checks and the production build pass, but do not establish that a real browser successfully completed every workflow against running services.
- **Definition and cross-reference results are only checked on synthetic expected payloads in offline pipeline tests.** Their live model resolution quality remains unmeasured.
- The application does not calculate financial ratios or provide legal advice; extracted records remain subject to human review.

No claim of real-world extraction accuracy is supported by these results.
