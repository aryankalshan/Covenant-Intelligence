# Risks and Limitations

| Area | Current limitation | Mitigation in this phase | Remaining work outside this phase |
| --- | --- | --- | --- |
| Extraction coverage | The chunk limit can leave part of a very long agreement unprocessed; OCR is not available for scanned pages. | New runs send all nonblank chunks to extraction without lexical screening. Report chunks left beyond the configured limit and retain full page text for human inspection. | Increase limits or add a measured pagination strategy only after cost/reliability evaluation; never infer absence from an empty result. |
| Citation checks | A quote on a page does not prove that it supports the legal interpretation. | Deterministically validate cited page, quote, source wording, and defined references; uncertain candidates remain drafts. | Human interpretation and review remain necessary. |
| Definitions/references | Heading and definition lookup is deterministic and limited; complex drafting may not resolve. | Preserve unresolved fields/uncertainty and require reviewer correction. | Expand and evaluate contract-specific cross-reference resolution without accepting unsupported outputs. |
| PDF text | Scanned/image PDFs are not OCR processed; extraction can be empty or incomplete. | Store per-page text and warnings/hashes; do not claim OCR support. | Decide whether to add OCR with source traceability and quality review. |
| Deadline rules | Only simple supported calendar-day period-end rules are calculated. Business-day and ambiguous rules need a human configured due date. | Leave due date unset and status `awaiting_setup`; expose deadline resolution to the user. | Define jurisdiction/calendar policy and explicit reviewer controls. |
| Financial compliance | The application does not calculate ratios, headroom, or covenant compliance. | Track only obligation periods, evidence references, and user-reported statuses. | None in current scope; financial calculation requires separate authorized scope. |
| Amendment matching | Category/name similarity can miss matches or suggest false matches. | Save proposals; require per-item reviewer decision and revalidate accepted candidates. | Evaluate matching quality and add stronger evidence-based comparison views. Never automatically apply. |
| Amendment removal | Partial extraction can omit a clause that remains in the amendment. | Store chunk/page coverage; incomplete cases are unresolved, not removed. Any removal proposal requires original evidence, full amendment text/PDF access, reviewer full-document attestation, and explanation. The prior obligation remains active until acceptance. | Coverage proves processing completeness only, not extraction recall or legal effect. Reviewer must inspect the full executed text. |
| Evaluation claims | Ten authored synthetic cases are too small and artificial to establish production extraction quality. | Integrity tests validate schema and evidence/page annotations; no accuracy claim is made from mock outputs. | Benchmark actual provider outputs against a larger labeled corpus and report uncertainty and per-category failures. |
| Identity/security | Seeded identities and `X-Dev-User` are development-only, without production authentication/session protections. | Clearly label development mode and enforce workspace/role checks in API routes. | Replace with reviewed production identity, sessions/tokens, secrets management, storage protections, and security testing before deployment. |
| Provider dependency | Live OpenRouter behavior, data terms, rate limits, and model output can vary. | Provider adapter, prompt/schema versioning, mock-based tests, sanitization, and explicit failures. | Configure and evaluate approved provider/model and data handling outside synthetic tests. |
| Audit immutability | Append-only behavior is enforced in the application ORM, not a tamper-proof external ledger. | Audit summaries are allowlisted; writes share transactions with state changes. | Production retention, privileged access controls, integrity monitoring, export, and backup policy. |
| Database migration | The project includes SQLite and PostgreSQL support, but migration behavior can differ by dialect/version. | Test a fresh SQLite Alembic upgrade and migrate the existing local DB additively. | Validate against the target PostgreSQL service in CI/deployment. |

This is a finance workflow aid, not legal advice or a substitute for reading the executed agreement. Use only public or synthetic documents in development.
